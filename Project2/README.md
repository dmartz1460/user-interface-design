# Project 2: 25Live UI Redesign

## Overview

The purpose of this project is to redesign an existing website UI that contains usability issues or core design flaws. Our chosen UI is `25Live`: the University of Cincinnati's event scheduler. 

- [Hosted Webpage](https://dmartz1460.github.io/user-interface-design/25live/)
- [Source Code](src/)
- [Demo](docs/25Live-Demo.mp4)

## Redesign

The redesign strategies for redesigning 25Live's dashboard, navigation, and search features are outlined in [REDESIGN.md](docs/REDESIGN.md). These strategies follow a basic process to analyze its design flaws and usability issues within the UI. An observational study and a survey will allow us to receive feedback from various users tasked with executing a series of actions within 25Live. As a result, user feedback and our initial design analysis will allow us to target specific areas of the UI to redesign.

25Live's redesign implementation decisions are outlined in [IMPLEMENTATION.md](docs/IMPLEMENTATION.md). These decisions reflect the redesign strategies detailed in the redesign document.

## Use of AI

AI tools were used during the design phase to standardize mockups for all teammates to code off of, as based on the final UI sketches. For more details, see [REDESIGN.md](docs/REDESIGN.md#final-sketch-mockups). Additionally, AI was periodically used to evaluate the usefulness and need for additional signifiers, such as a dedicated dashboard button versus a clickable 25Live logo. AI was not used in the original sketching or ideation process, and all AI-generated designs were treated as exploratory ideas rather than final decisions.

During the implementation phase, AI tools were used as a development assistant. AI helped inspect existing code, diagnose potential bugs, draft some features, and ensure consistent branding usage across all modules and between all teammates' code. Testing and quality assurance were handled independent of AI tools.
